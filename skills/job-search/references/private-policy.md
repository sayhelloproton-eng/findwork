# 三项私有策略｜Job Search Skill 输入契约

本文件是**公开的说明**，不是私人资料。Job Search Skill 执行岗位评估必须有三个独立、已确认且有实际内容的本机私有文件（均相对于 Findwork 仓库根目录）：

| 分类 | 唯一路径 | 应包含什么 |
|---|---|---|
| 个人画像 | `.private/job-search/candidate-profile.md` | 用户已确认的主要项目/工作经历、能力、可迁移经验、真实能力缺口；事实与推测分开 |
| 求职偏好 | `.private/job-search/target-roles.md` | 目标岗位的工作内容、期望行业、正向偏好、优先级和用户确认的限制；“加分”与“硬条件”分开 |
| 排除条件 | `.private/job-search/exclusions.md` | 用户明确拒绝的岗位、行业、公司类别和不可接受要求，以及判定依据；不得扩大黑名单 |

## AI 启动评估前的检查

1. 定位 Findwork **仓库根目录**（不要按运行终端当前目录盲目拼接），逐个核实三份文件存在、非空、可读，确实包含用户确认过的策略。
2. 读取全部三项，检查逻辑冲突、有效性和是否需要新的职业事实。可以引用用户当场提供的简历/事实进行核实，但不要自行臆造工作经历、学历、薪资或英语能力。私人资料中的旧工作区绝对路径**可能过期**，外部源不可达时说明缺证据，不依赖旧仓库才能运行。
3. 某项文件缺失/空白/未确认：向用户说明该项用途、询问必要信息；获确认后仅写本机对应私有文件。**不得写入公开 references、README、样例测试、Git 或日志。** 不以“没有禁忌”“不限行业”等 AI 猜测当作用户偏好。
4. 用户明确声明“无额外偏好”或“无排除项”时可以将该声明作为该项有效输入，前提是记录确认事实；无需强迫虚构偏好。
5. 三项都有效才能对岗位给出正式 WORTH/PASS 并写回 DB。若依赖缺失，已采集数据仍可安全导入 DB 和展示，待评估岗位保持 PENDING，禁止无策略时对外联系。
6. 策略修改不自动翻转已有 WORTH/PASS，也不自动重发消息。按用户要求进行显式复核，使用当前证据和版本写入结果。

## 隐私与 Git

- 根 `.gitignore` 忽略整个 `.private/`，三份实际文件不在版本控制中；即使用户已经有本机实际内容，也不能复制进公开 Skill 文件。
- 不把简历全文、求职偏好清单、排除公司清单复制到对外的 Git 变更说明、PR、测试快照或平台消息。
- 原始岗位数据/通信回执/认证信息同样留在私有运行目录，不应当通过公开 Skill 打包发布。
- 私有目录历史上可能还有 `.private/job-search/evaluation.md`；它不是第四项必需输入。若内容与三项策略冲突或承载额外个性化规则，先请用户确认是否合并，勿默默引入新规则。
- 若用户安装的是公开仓库副本，**三份私有文件不会跟随 Git 自动下载**；AI 须按上面步骤协助用户自行准备后才能评估。

公开引用：`references/candidate-profile.md`、`references/target-roles.md`、`references/exclusions.md` 只说明每项如何使用；通用的评估过程以 `references/evaluation.md` 为准。
