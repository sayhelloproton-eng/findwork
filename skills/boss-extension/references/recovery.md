# 异常与安全停止

- 找不到 BOSS 标签或没登录：核对当前 Chrome Profile，不猜账号。
- Refresh 无 List：核对求职期望索引、自然响应和下载回执，不连续盲刷新。
- Scroll 无新批次：确认是否到末端，不高速重复滚动。
- Detail 无响应或职位 ID 不一致：记录失败项并停止，不直接发独立详情请求。
- Hook/Worker 丢失或下载 UNKNOWN：查看只读诊断和已有文件，未确认副作用前禁止重试。
- Greet：业务明确拒绝记 FAILED，副作用或回执不确定才记 UNKNOWN；入队/领取没有发送证据记未结算，不把三者混为一谈。
- 验证码、安全校验、限流：停止，不规避平台控制。

用户明确要求新一轮完整采集时可在前一任务安全终态使用 fresh=1；只能重置本轮判定缓存，不能删除历史原始 JSON、SQLite 或成功沟通记录。

## Greet：只在同一页面核实与恢复

打开不带参数的 actions/greet/greet.html。AI核对失败原因与回执，用户不看JSON。岗位关闭/不存在保留失败，不重发；有剩余队列可在同页点继续。次数提醒由用户在BOSS正常页面确认，AI不代点。次数/额度导致的明确失败且当天成功未满150时，用户可点该行重新发送：它打开同一个带重发参数的Greet页，再走正式重新领取与发送前校验。BOSS以前返回的上限只作为错误信息，不是本地硬锁；再次拒绝则保留失败、暂停，不自动循环。关闭、其他业务失败、风控、UNKNOWN和未落盘都不能重发。

领取响应丢失不能认定未领取，先通过主系统get读回；只有正式核实未入队且无副作用，才按主控database.md恢复。禁止直接修改存储、数据库或另建临时恢复页/脚本。旧Greet Status仅跳转同一Greet默认页。下载文件是用户数据，清理界面不删除它们。业务成功日按finishedAt，而非下载完成时间。
