# 采集与联系工作流

## 完整职位采集
确认登录、唯一职位列表与求职期望位置 → auto Detail 页面 → Refresh 收到自然 List 和首条 Detail → 按 jobId 唯一对应剩余 DOM 卡片 → 单条下载 COMPLETE → 本批15条完成才 Scroll → 指定批次或故障终止。20批即300条目标；没有足够真实数据必须如实报告。fresh=1 重新下载全部自然详情，不把已有文件算进本次结果。

## 已有 List 需要 Detail
优先复用已核对的最新 List，通过单批 Detail 入口逐条获取自然响应；一份 List 里的 encryptJobId 与 Detail 里的职位 ID 对应，不可以混用不同岗位参数。

## 筛选、入库和沟通
逐条核验原始文件后，扩展工作即结束。可按 fields.md 的证据级别判断猎头、代理等不确定字段；若用户另行要求导入数据库，由独立的外部脚本、应用或数据库客户端自行处理去重、入库与读回，不属于扩展功能。Greet 是真实沟通，不是正式投递，只有用户对具体职位明确授权后才执行。成功、失败、UNKNOWN 分开统计，UNKNOWN 不再次发送。

## 异常
Greet 只打开不带参数的 actions/greet/greet.html 查看队列、错误和人工提示；参数页只入队。其他采集动作先看控制页和下载记录，必要时打开只读诊断。不要无限 Refresh、Scroll、Reload；站点安全校验、无新列表或未知副作用必须停止。
